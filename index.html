The job in one sentence

A car company builds software for the car's screens. Your job is to prove that the screens show the right thing at the right time — and when they don't, to write a bug report so clear that a developer can fix it without asking you anything.

The 3 things this client wants from you

The job description (JD) is long, but it boils down to three skills. Every answer you give in the interview should prove one of them.

1

Test the screens by hand

Manual testing of the instrument cluster and infotainment screen. You compare what you see with the written requirement.

2

Run automation and explain failures

You start the customer's automated test suite, read the results and decide for every failure: real bug, script problem, or test-bench problem.

3

Write excellent bug reports

Clear title, exact steps, logs and traces, and the impact. A developer must be able to reproduce the bug on the first try.

How to use this site

  1. Read the chapters in order. Each chapter starts with the simple idea, then the details, then "Say this in the interview".
  2. Don't memorise words, understand the idea. If you meet a word you don't know, open the Dictionary. Every word is explained there with an example.
  3. Practise. Do the spot-the-defect drills with the timer, take the quiz, and answer the interview questions out loud before you open the model answer.
  4. Tick "I understood this page" at the bottom of each page. Your progress shows in the menu on the left.

The 10 questions you must be able to answer

Based on the interviewer's question pattern, these are the most likely. Each links to a full, simple answer.

  1. Explain your testing process from requirement to release.
  2. What makes a good defect report?
  3. What do you do after a developer fixes a defect?
  4. Explain your regression strategy.
  5. How do you select regression tests with thousands of tests and little time?
  6. Should every fixed defect be added to regression? Examples.
  7. How do you avoid duplicate Jira tickets?
  8. When would you NOT create a defect ticket?
  9. Explain boundary value analysis with an automotive example.
  10. The snowflake: which exact temperatures would you test and why?
Be honest

The model answers use placeholders like [your project]. Replace them with your real experience. Interviewers ask follow-up questions, so never claim work you haven't done. Saying "I haven't used that tool yet, but this is how I would approach it…" is a strong answer.
